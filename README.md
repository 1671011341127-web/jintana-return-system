# Jintana Return Management — Prototype 0.2

## สิ่งที่ทำได้ในต้นแบบนี้
- นำเข้า Excel หลายไฟล์ อ่านชีต `Detail` และตรวจคอลัมน์สำคัญจากไฟล์จริง
- ใช้ `SHIPTO_CODE`, `ITEM_CODE`, `ITEM_NAME`, `RETRUN_QTY`
- รวมจำนวนตามร้านและ SKU พร้อมแยกประเภทจากชื่อสินค้า (กฎเริ่มต้นแก้ไขได้)
- ร้านเดียวเข้าร่วมได้หลายกลุ่ม SKU โดยไม่ตัด SKU อื่นทิ้ง; พนักงานที่มอบหมายให้ร้านจะถูกใช้ร่วมกันทุก SKU
- ติดตามการเสร็จเป็นราย SKU และแสดงร้านว่าเสร็จสมบูรณ์เมื่อทำครบทุก SKU ที่นำเข้าแล้ว
- แนะนำกลุ่มตาม SKU ได้ 3 โหมด: อัตโนมัติ / เลือกเอง / แนะนำและจัดอันดับ
- ตั้งความจุกล่องตามประเภทสินค้า
- ยืนยันกลุ่ม, มอบหมายพนักงานในระดับร้าน, ยืนยันเสร็จเป็นราย SKU, ยกเลิกกลุ่ม
- บันทึกกิจกรรมและส่งออกประวัติเป็น Excel
- หน้าจอ responsive และเมนูด้านบน

## รันบนเครื่อง
ต้องมี Node.js 18 ขึ้นไป

```bash
npm install
npm run dev
```

เปิด URL ที่ Vite แสดงใน Terminal

## ข้อจำกัดที่ต้องทราบ
เวอร์ชันนี้เป็น **ต้นแบบในเครื่อง (local prototype) 0.2** ข้อมูลจะเก็บใน localStorage ของเบราว์เซอร์และเครื่องที่เปิดใช้งานเท่านั้น:
- ยังไม่มีระบบล็อกอินจริง
- ยังไม่ซิงก์ข้อมูลข้ามเครื่อง/ข้ามผู้ใช้
- ยังไม่อัปโหลดไฟล์ต้นฉบับไป cloud storage
- ตัวเลือกบทบาทหัวหน้า/พนักงานเป็นตัวจำลองหน้าจอ ไม่ใช่การควบคุมสิทธิ์ที่ปลอดภัย

จึงยังไม่ควรนำไปใช้กับข้อมูลการทำงานจริงจนกว่าจะเชื่อม Supabase, ตั้งค่า Auth/Storage/RLS และทดสอบการทำงานพร้อมกัน

## เตรียมระบบออนไลน์ด้วย Supabase
1. สร้าง Supabase project
2. เปิด SQL Editor แล้วรัน `supabase/schema.sql`
3. สร้าง Storage bucket ชื่อ `return-files` แบบ private
4. เพิ่ม environment variables ใน `.env` (ดู `.env.example`)
5. เชื่อม client และ Auth ในขั้นตอนพัฒนาถัดไป
6. ตั้งบัญชีผู้ใช้ใน `profiles` และกำหนด `role` เป็น `manager` หรือ `employee`
7. ทดสอบการนำเข้าพร้อมกัน, ป้องกันร้านซ้ำแบบ transaction/RPC, audit log และ realtime subscription

## จุดที่ต้องตรวจร่วมกับผู้ใช้ก่อนใช้งานจริง
- กฎแยกประเภทจาก `ITEM_NAME` ต้องตรวจชื่อสินค้าจริงทุกกลุ่มและเติม keyword ให้ครบ
- การจับคู่ร้านใช้ `SHIPTO_CODE` และสถานะจัดกลุ่มแยกตามคู่ `SHIPTO_CODE + ITEM_CODE` เพื่อให้ร้านเดียวมีหลาย SKU ได้
- หากมีเอกสารหลายฉบับของร้านเดียวกันใน batch ต่างกัน ระบบปัจจุบันจะไม่เพิ่มรายการใหม่ให้ร้านที่จัดกลุ่มแล้ว ต้องออกแบบ flow สำหรับเอกสารเพิ่มเติม/การคืนซ้ำในรอบถัดไปให้ชัดเจน
- การจัดกลุ่มจริงควรมี transaction ฝั่งฐานข้อมูล ไม่พึ่งการตรวจซ้ำเฉพาะหน้าเว็บ
- ควรเพิ่มการคืนร้านกลับคิวเมื่อยกเลิกกลุ่ม พร้อมประวัติเดิมแบบ immutable

## โครงสร้าง
- `src/App.jsx` — หน้าจอและ workflow
- `src/engine.js` — อ่าน/จัดกลุ่ม/แนะนำ
- `src/styles.css` — responsive UI
- `supabase/schema.sql` — schema เริ่มต้นและ policies (ต้องผ่าน security review ก่อน production)


## เวอร์ชัน 0.3 (ปรับปรุงการจัดกลุ่ม)
- โหมดเลือกเอง: เลือกร้านเฉพาะที่ต้องการรวมในกลุ่ม SKU นั้นก่อนยืนยันได้
- ระบบตรวจซ้ำระดับรหัสร้าน + SKU ก่อนยืนยันกลุ่ม
- ปรับคำแนะนำเป็น First-Fit Decreasing เพื่อพยายามใช้ความจุกล่องให้เหมาะสม โดยไม่รวม SKU ต่างกัน
- ร้านที่มีจำนวนเกินความจุกล่องจะแสดงคำเตือนและไม่ถูกตัดจำนวนทิ้ง
- แยกคำจำแนก “เสื้อกล้ามเด็ก” ออกจาก “เสื้อกล้าม” ทั่วไป

ข้อจำกัดยังคงเดิม: เป็นต้นแบบ localStorage ยังไม่ใช่ระบบออนไลน์หลายผู้ใช้ และต้องเชื่อม Supabase/Auth/Storage พร้อมทดสอบกับไฟล์จริงและตรวจสอบสิทธิ์ก่อนใช้งานจริง
